# 코드 리뷰 템플릿 (Code Review Template)

코드 리뷰 요청 및 수행 시 사용하는 종합 템플릿입니다.

---

## 리뷰 정보 입력

| 항목 | 값 |
|------|---|
| PR/변경 제목 | |
| 변경 유형 | 기능 / 버그 수정 / 리팩토링 / 문서 |
| 변경 파일 수 | |
| 리뷰 초점 | 로직 / 보안 / 성능 / 스타일 |

---

## 리뷰 요청 프롬프트

### 일반 코드 리뷰

```
InterfaceHive 코드 변경을 리뷰해줘.

## 변경 개요
- 목적: [변경 목적]
- 관련 이슈: [이슈 번호]

## 변경 파일
- [파일 1]: [변경 내용 요약]
- [파일 2]: [변경 내용 요약]

## 변경 코드
### [파일명]
```[language]
[코드 붙여넣기]
```

## 리뷰 요청 사항
1. 로직 정확성
2. 엣지 케이스 처리
3. 에러 핸들링
4. 코드 스타일
5. 테스트 충분성

## 우려 사항 (있다면)
- [특별히 검토가 필요한 부분]

## 컨텍스트
- 관련 기존 코드: [파일 경로]
- 참고 문서: [링크]
```

## PR 전체 리뷰 프롬프트

```
InterfaceHive PR을 전체 리뷰해줘.

## PR 정보
- 제목: [PR 제목]
- 작성자: [작성자]
- 목적: [PR 목적]
- 관련 이슈: [이슈 번호]

## 변경 파일 목록
- [파일 1]
- [파일 2]
- ...

## 각 파일 변경 내용
### [파일 1]
```[language]
[diff 또는 전체 코드]
```

### [파일 2]
```[language]
[diff 또는 전체 코드]
```

## 리뷰 요청
### 전체 관점
1. 변경이 목적에 부합하는가?
2. 설계가 적절한가?
3. 기존 코드와 일관성이 있는가?

### 세부 관점
1. 각 파일별 이슈
2. 보안 우려
3. 성능 우려
4. 테스트 충분성

### 개선 제안
1. 필수 수정 사항 (Blocker)
2. 권장 수정 사항 (Should fix)
3. 선택 제안 (Nice to have)

## 출력 형식
### [파일명]
- ✅ 좋은 점: [칭찬할 부분]
- ❌ 문제점: [수정 필요]
- 💡 제안: [개선 아이디어]

### 전체 평가
- 승인 가능 여부
- 주요 우려 사항
```

### 로직
- [ ] 엣지 케이스 처리
- [ ] 에러 핸들링

### 보안
- [ ] 입력 검증
- [ ] 권한 확인

## 코드 리뷰 베스트 프랙티스

### 효과적인 리뷰 요청

```markdown
## 좋은 리뷰 요청 예시

### PR 제목
[Feature] 프로젝트 검색 필터 추가

### 변경 사항
- 프로젝트 목록에 난이도별 필터 추가
- 태그 기반 검색 구현
- 검색 결과 페이지네이션

### 테스트
- [x] 필터 조합 테스트
- [x] 빈 결과 처리 테스트
- [x] 페이지네이션 테스트

### 리뷰 포인트
1. 쿼리 성능이 적절한지 확인 부탁드립니다 (views.py:45-60)
2. 필터 UI 접근성 확인 필요합니다

### 스크린샷
[UI 변경 스크린샷]
```

### 건설적인 피드백

```markdown
## 좋은 피드백 예시

❌ "이 코드 이상해요"
✅ "이 부분에서 N+1 쿼리가 발생할 수 있어요.
    `select_related('host_user')`를 추가하면 해결됩니다."

❌ "왜 이렇게 했어요?"
✅ "이 접근 방식의 이유가 궁금합니다.
    `Strategy 패턴`을 적용하면 확장성이 좋아질 것 같은데,
    어떻게 생각하시나요?"

❌ "변수명 바꾸세요"
✅ "`data` 대신 `projectList`처럼 구체적인 이름이
    코드 이해에 도움이 될 것 같습니다."
```
