# 버그 수정 템플릿 (Bug Fix Template)

버그를 분석하고 수정할 때 사용하는 종합 템플릿입니다.

---

## 버그 정보 입력

| 항목 | 값 |
|------|---|
| 버그 제목 | |
| 심각도 | Critical / High / Medium / Low |
| 재현 가능 | 항상 / 가끔 / 특정 조건 |
| 영향 범위 | |
| 발견 환경 | 로컬 / 스테이징 / 프로덕션 |

---

## Phase 1: 버그 분석

### 프롬프트

```
InterfaceHive에서 발생한 버그를 분석해줘.

## 버그 설명
[버그 현상 상세 설명]

## 재현 단계
1. [단계 1]
2. [단계 2]
3. [단계 3]

## 예상 동작
[정상적으로 동작해야 하는 방식]

## 실제 동작
[현재 잘못된 동작]

## 환경 정보
- 브라우저/클라이언트: [버전]
- OS: [버전]
- 백엔드 버전: [커밋 해시]
- 프론트엔드 버전: [커밋 해시]

## 에러 로그 (있다면)
```
[에러 로그 붙여넣기]
```

## 스크린샷 (있다면)
[스크린샷 설명]

## 질문
1. 이 버그의 근본 원인은 무엇인가?
2. 영향을 받는 다른 기능이 있는가?
3. 어떤 파일/코드를 확인해야 하는가?
```

## Phase 2: 원인 조사

### 2.1 코드 추적

```
버그와 관련된 코드를 추적해줘.

## 증상
[Phase 1에서 분석된 증상]

## 추적 시작점
- 파일: [시작 파일 경로]
- 함수/컴포넌트: [이름]

## 조사 요청
1. 관련 코드 흐름 추적
2. 최근 변경 사항 확인 (git log)
3. 유사 패턴의 다른 코드 확인
4. 잠재적 원인 목록 작성

## 의심되는 영역
- [영역 1]
- [영역 2]
```

### 2.2 데이터 분석 (해당시)

```
버그와 관련된 데이터 상태를 분석해줘.

## 문제 데이터
- 모델: [모델명]
- ID: [해당 ID]
- 조건: [데이터 조건]

## 조사 요청
1. 데이터 무결성 확인
2. 관련 데이터 관계 확인
3. 데이터 불일치 탐지
4. 마이그레이션 이력 확인

## 쿼리 (필요시)
```sql
-- 데이터 조회 쿼리
```
```

## Phase 5: 테스트

### 5.1 회귀 테스트 작성

```
[버그] 수정에 대한 회귀 테스트를 작성해줘.

## 수정된 코드
[수정된 코드]

## 테스트 요구사항
### 버그 재현 테스트
- 수정 전 실패, 수정 후 성공하는 테스트

### 정상 케이스 테스트
- 기존 정상 동작 확인

### 엣지 케이스 테스트
- 관련 경계 조건

## 테스트 코드
```[language]
# 재현 테스트
def test_[bug_description]_is_fixed():
    # 버그 상황 설정
    # 동작 실행
    # 정상 결과 확인
```

## 제약조건
- 명확한 테스트 이름 (버그 설명 포함)
- 독립적으로 실행 가능
- 실패 메시지 명확
```

### 5.2 수동 테스트 체크리스트

```
[버그] 수정의 수동 테스트 체크리스트를 작성해줘.

## 재현 테스트
- [ ] 원래 재현 단계로 버그 확인 불가

## 정상 동작 확인
- [ ] [정상 케이스 1]
- [ ] [정상 케이스 2]

## 관련 기능 확인
- [ ] [관련 기능 1]
- [ ] [관련 기능 2]

## 브라우저/환경 테스트
- [ ] Chrome
- [ ] Firefox
- [ ] Safari
- [ ] Mobile

## 성능 확인 (해당시)
- [ ] 응답 시간 변화 없음
- [ ] 메모리 사용량 정상
```

3. 코드 품질은 적절한가?
4. 테스트 커버리지는 충분한가?
5. 문서 업데이트가 필요한가?

## 배포 전 확인
- [ ] 모든 테스트 통과
- [ ] 코드 리뷰 완료
- [ ] 수동 테스트 완료
- [ ] 롤백 계획 수립

## 빠른 시작 (Quick Start)

간단한 버그 수정 요청:

```
InterfaceHive에서 [버그 현상]이 발생해.

## 재현 방법
1. [단계]
2. [단계]

## 에러 메시지 (있다면)
```
[에러 내용]
```

## 관련 파일
- [파일 경로]

이 버그를 분석하고 수정해줘.

## 제약조건
- 최소한의 변경으로 수정
- 기존 동작 유지
- 회귀 테스트 추가
```

## 심각도별 가이드

### Critical (즉시 수정)
- 서비스 중단
- 데이터 손실/오염
- 보안 취약점

```
[긴급] InterfaceHive에서 [Critical 버그]가 발생했어.

## 증상
[증상 설명]

## 영향
- 영향받는 사용자: [범위]
- 서비스 상태: [상태]

## 에러 로그
```
[에러 로그]
```

긴급히 분석하고 최소한의 수정으로 해결해줘.
핫픽스 후 근본적인 수정은 별도로 진행할 수 있어.
```

### High (빠른 수정)
- 주요 기능 장애
- 다수 사용자 영향

### Medium (일반 수정)
- 부분 기능 이슈
- 워크어라운드 존재

### Low (개선)
- 미미한 영향
- UI/UX 사소한 이슈

## 공통 버그 패턴

### N+1 쿼리 문제

```
[엔드포인트/페이지]에서 느린 로딩이 발생해.
django-debug-toolbar로 확인하니 N+1 쿼리 문제로 보여.

## 위치
- 파일: [파일 경로]
- 쿼리 수: 예상 1개 → 실제 100+개

select_related/prefetch_related를 적용해서 수정해줘.
```

### 인증/권한 문제

```
[엔드포인트]에서 인증/권한 문제가 발생해.

## 증상
- 예상: [예상 동작]
- 실제: [실제 동작 - 401/403 등]

## 관련 코드
- View: [파일 경로]
- permission_classes: [현재 설정]

권한 설정을 확인하고 수정해줘.
```

### 타입 에러 (TypeScript)

```
TypeScript 타입 에러가 발생해.

## 에러 메시지
```
[TSC 에러 메시지]
```

## 관련 파일
- [파일 경로]

타입을 수정하되, 타입 안전성을 유지해줘.
any 사용은 피하고 적절한 타입을 정의해줘.
```

### Race Condition

```
[기능]에서 가끔 비정상 동작이 발생해.
Race condition으로 의심돼.

## 재현 조건
- [조건 설명]

## 관련 코드
- [파일 경로]

동시성 문제를 분석하고 적절한 동기화를 추가해줘.
```
